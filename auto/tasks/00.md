# 00 — Pin the current TornadoVM CUDA baseline

## Goal
Establish the exact TornadoVM source, JDK, GPU, CUDA toolkit/runtime, driver, and build state before any demo or content claim is made.

## Steps

- Clone or refresh TornadoVM `develop` outside this repository.
- Record `TORNADO_SHA=$(git rev-parse HEAD)` and the date/time.
- Build **only** the CUDA backend using the current documented command, preferring `make BACKEND=cuda` when supported by the checked-out tree.
- Source `setvars.sh` and run `tornado --devices`.
- Run one trivial CUDA example and capture stdout/stderr.
- Inspect `tornado --help` and relevant source directories for the current CUDA backend and Hybrid API entry points.
- Capture GPU name, driver, CUDA toolkit/runtime, JDK version, Maven version, compiler version, and TornadoVM SHA under `results/manifest/`.
- Document anything that differs from the stated talk abstracts in `docs/claims.md` as either observed, documented, or open.

## Acceptance

- A committed manifest exists.
- TornadoVM `develop` builds with the CUDA backend only, or the failure is fully captured.
- `tornado --devices` is captured from the exact SHA.
- A trivial CUDA execution is captured and validated, or marked blocked with evidence.
