# 01 — Inventory and probe the current Hybrid API

## Goal
Determine exactly what the current TornadoVM CUDA tree can do for Java + CUDA runtime + NVIDIA libraries.

## Steps

Inspect the pinned TornadoVM source for the Hybrid API and verify, with runnable examples/tests where possible:

- Java GPU kernel task construction;
- CUDA runtime API access;
- cuBLAS/cuBLASLt provider;
- cuFFT provider;
- cuDNN provider;
- cuSPARSE provider;
- CUTLASS provider;
- buffer/data-sharing semantics between TornadoVM tasks and native-library tasks;
- stream/command-queue behavior;
- supported datatypes and current limitations;
- current examples and tests.

Capture source paths, commands, actual outputs, and precise caveats in `docs/claims.md` and `results/raw/`.

## Acceptance

- Each claimed provider is classified as observed, source-backed, documented, hypothesis, or blocked.
- At least one executable probe exists for the core Hybrid API composition path.
- Unsupported or missing capabilities are explicitly recorded rather than inferred.
