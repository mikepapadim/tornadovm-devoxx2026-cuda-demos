# 08 — Profile GPULlama3 inference with NVIDIA tools

## Goal
Profile the reproducible LLM inference path to explain where GPU time and host time are spent and to identify metrics that make sense in the second Devoxx talk.

## Coverage

Use installed/current NVIDIA profiling tools, prioritising `nsys` for end-to-end timelines and CUDA API/kernel-launch behavior and `ncu` for representative hot kernels when feasible.

Capture, where available and meaningful:

- tokens/s and latency breakdown;
- CUDA kernel launch count and launch overhead;
- GPU utilization and memory footprint;
- dominant kernels and their share of execution time;
- achieved occupancy and memory throughput;
- arithmetic/instruction characteristics;
- tensor-core activity when the actual current path uses it;
- host synchronization or transfer overhead;
- quantization-specific differences between verified Q4/Q8/FP16 paths.

Do not claim a metric that the profiler did not expose or that came from a run with materially different settings.

## Acceptance

- Successful profile or fully captured blocker for the main LLM path.
- Metrics extracted to machine-readable artifacts.
- `docs/claims.md` references every profiler-derived statement.
- `docs/demo-runbook.md` contains exact commands and a small presenter-focused metric set.
